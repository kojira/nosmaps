# nosmaps UI mock

Nostr周辺ツールの探し方を比較するための、**操作可能な純粋静的サイト**です。

> **重要:** 掲載名は原則として架空です。状態（active / stale / dead / unknown）、観測日時、根拠、ログはすべてUI確認用のモックであり、実在サービスの稼働状況を示しません。Nostrには未接続です。

## 4案の狙い

- **A「目的から探す」** — 初心者向け。専門用語ではなく「何をしたいか」から候補へ進む。
- **B「一覧・絞り込み・2〜3件比較」** — 比較検討する人向け。高密度な一覧、複数条件、最大3件の比較で差分を掴む。
- **C「カテゴリを辿る探索」** — 周辺領域も発見したい人向け。カテゴリを歩き、検索語を決めずに探索する。
- **D「NIP探索・比較」** — 既存利用者・開発者向け。NIPから架空ツールを逆引きし、最大3件をマトリクス比較する。

トップ画面には、比較してほしい観点（次の操作、到達速度、状態根拠への信頼、再探索したさ）を表示しています。

## 共通データ

全4案で `data.js` 内の同じ36件の架空データを共有します。カテゴリ、用途、環境、ライセンス、状態、判定根拠、観測日時、観測ログを持ちます。観測値はすべてモックと画面内で明記しています。

## 操作と確認手順

1. トップからA/B/C/Dのいずれかを開く。
2. 目的選択（A）、検索・カテゴリ・状態・環境フィルタ（全案）、カテゴリ巡回（C）を試す。
3. カードの「詳細を見る」から状態の根拠と観測日時を確認する。
4. 2〜3件の「比較」を選び、画面下の「比較する」から横比較する。
5. ヘッダーから「候補を投稿」「キュレーション」「作者訂正」を開き、入力・イベントプレビュー・未送信状態を確認する。
6. 各案下部の **UI STATE LAB** で loading / empty / error / partial / offline を切り替える。
7. 幅375px前後のモバイル表示、および Tab / Shift+Tab / Enter / Space / Esc での操作を確認する。

## Nostr未接続

候補投稿・キュレーション・作者訂正は操作イメージのみです。秘密鍵へのアクセス、署名、イベント送信、リレー接続は実装していません。フォーム送信後も「プレビュー確認済み（未送信）」になるだけです。

## 永続的なアーキテクチャ原則

**このプロジェクトは、バックエンド、専用API、永続DB、中央インデクサを未来永劫作りません。** 静的ファイルとして配信し、将来データ接続を行う場合もブラウザからNostr等の分散プロトコルを直接利用する前提です。

## ローカル確認

```sh
python3 -m http.server 4173
# http://localhost:4173/
```

ビルド工程はありません。`index.html` / `nip-explorer.html` / CSS / JavaScript がそのまま配信物です。過剰な依存を避けるため、アプリ本体のnpm依存はゼロです。

## 第4案 D「NIP探索・比較」

`nip-explorer.html` は、既存Nostr利用者・開発者が **NIPを起点に架空ツールを逆引きし、対応状況と根拠を比較する** 別ページです。A/B/Cは従来どおり `index.html` で操作でき、トップとヘッダーからD案へ移動できます。

- NIP番号・正式英語見出し・短い用途から検索
- 選択NIPに対応する架空ツールの逆引き
- OS・カテゴリ・ツール状態・NIP対応状況で絞り込み
- 各ツールの使用NIP一覧と、`実装 / 部分対応 / 予定 / 不明` の区別
- 最大3件のNIPマトリクス比較
- 各セル／カードから、架空の根拠・観測日時・観測主体へ到達
- loading / empty / error / partial / offline 状態の表示確認
- モバイルでは主要NIP検索を先に置き、選択条件要約と展開式詳細フィルターを採用

### D案の確認手順

1. `nip-explorer.html` を開く（初期選択は NIP-57）。
2. 検索欄で `57` / `zaps` / `暗号化` などを検索し、NIPを選ぶ。
3. 逆引き結果からOS・カテゴリ・状態・対応状況を絞る。
4. 「根拠・観測詳細」でモック根拠、観測日時、観測主体、公式NIP一次資料への導線を確認する。
5. 2〜3件を「比較に追加」し、「マトリクスで比較」を開く。
6. 幅375pxで、主要検索→選択条件要約→詳細フィルターの順と横溢れがないことを確認する。
7. UI STATE LABで loading / empty / error / partial / offline を切り替える。

### NIP一次資料とモック制約

NIP番号・英語見出し・用途ラベルは、公式 `nostr-protocol/nips` リポジトリの commit `656cecc7c0a815b6a2b218d3b5d6f078b3f4dbab`（2026-08-15確認）に照合しています。採用NIPは 01 / 02 / 05 / 09 / 11 / 19 / 21 / 23 / 25 / 42 / 44 / 46 / 47 / 57 / 65 / 78 です。

**一方、36件のツール名、各ツールのNIP対応状況、根拠、観測日時、観測主体はすべて架空のUIモックです。** 実在するクライアント、リレー、ライブラリ等の対応状況や品質評価として利用できません。`不明` は確認材料不足による保留であり、未実装・非対応という否定評価ではありません。

共通架空データは `data.js` に分離し、A/B/CとDで同じ36件を読み込みます。DだけがNIP対応情報を利用します。構成は引き続き純粋な静的ファイルのみで、バックエンド、専用API、永続DB、中央インデクサはありません。
