# nosmaps UI mock

Nostr周辺ツールの探し方を比較するための、**操作可能な純粋静的サイト**です。

> **重要:** 掲載名は原則として架空です。状態（active / stale / dead / unknown）、観測日時、根拠、ログはすべてUI確認用のモックであり、実在サービスの稼働状況を示しません。Nostrには未接続です。

## 4案の狙い

- **A「目的から探す」** — 初心者向け。専門用語ではなく「何をしたいか」から候補へ進む。
- **B「一覧・絞り込み・2〜3件比較」** — 比較検討する人向け。高密度な一覧、複数条件、最大3件の比較で差分を掴む。
- **C「カテゴリを辿る探索」** — 周辺領域も発見したい人向け。カテゴリを歩き、検索語を決めずに探索する。
- **D「機能探索・比較（NIP裏付け）」** — 既存利用者向け。使いたい機能や利用場面から架空ツールを逆引きし、最大3件を機能マトリクスで比較する。NIPは技術的な根拠として辿れる。

トップ画面には、比較してほしい観点（次の操作、到達速度、状態根拠への信頼、再探索したさ）を表示しています。

## 共通データ

全4案で `data.js` 内の同じ36件の架空データを共有します。カテゴリ、用途、環境、ライセンス、状態、判定根拠、観測日時、観測ログを持ちます。観測値はすべてモックと画面内で明記しています。

## 操作と確認手順

1. トップからA/B/C/Dのいずれかを開く。
2. 目的選択（A）、検索・カテゴリ・状態・環境フィルタ（全案）、カテゴリ巡回（C）を試す。
3. カードの「詳細を見る」から状態の根拠と観測日時を確認する。
4. 2〜3件の「比較」を選び、画面下の「比較する」から横比較する。
5. ヘッダーから「候補を投稿」「キュレーション」「作者訂正」を開き、入力・イベントプレビュー・未送信状態を確認する。
6. 各案下部の **UI STATE LAB** で loading / empty / error / partial / offline を切り替える。
7. 幅375px前後のモバイル表示、および Tab / Shift+Tab / Enter / Space / Esc での操作を確認する。

## Nostr未接続

候補投稿・キュレーション・作者訂正は操作イメージのみです。秘密鍵へのアクセス、署名、イベント送信、リレー接続は実装していません。フォーム送信後も「プレビュー確認済み（未送信）」になるだけです。

## 永続的なアーキテクチャ原則

**このプロジェクトは、バックエンド、専用API、永続DB、中央インデクサを未来永劫作りません。** 静的ファイルとして配信し、将来データ接続を行う場合もブラウザからNostr等の分散プロトコルを直接利用する前提です。

## ローカル確認

```sh
python3 -m http.server 4173
# http://localhost:4173/
```

ビルド工程はありません。`index.html` / `nip-explorer.html` / CSS / JavaScript がそのまま配信物です。過剰な依存を避けるため、アプリ本体のnpm依存はゼロです。

## 第4案 D「機能探索・比較（NIP裏付け）」

`nip-explorer.html` は既存URLを維持したまま、**機能名・短い利用場面を起点に架空ツールを逆引きする**ページへ改修しています。A/B/Cは従来どおり `index.html` で操作できます。

- 投稿・返信、DM、検索、画像・動画、通知、マルチアカウント、外部署名・リモート署名、Wallet・Zap、長文、チャンネル・コミュニティを主要探索軸にする
- 「今のツールの代替」「この機能が使える別ツール」を探す導線
- dead（終了／到達不能）は初期結果から除外し、明示チェック時だけ表示。表示時は同機能の稼働候補へ戻る導線を付ける
- OS、カテゴリ、更新状態、提供形態、OSS、最終観測を含む、最大3件の機能マトリクス比較
- 各機能の詳細から、対応／部分対応／予定／不明、架空根拠、架空観測日時、架空観測主体、関連NIPへ到達
- 詳細フィルターからNIP番号・名称・用途による高度な絞り込み
- OSS表示には外部の存在しないURLを作らず、`#mock-source-*` の安全なページ内モック説明を使う
- loading / empty / error / partial / offline 状態の表示確認
- モバイルでは価値提案、主要検索、主要機能、候補導線をファーストビュー付近に置き、詳細フィルターは折りたたむ

### D案の確認手順

1. `nip-explorer.html` を開く（初期選択は「投稿・返信」）。
2. 検索欄で `DM` / `zapを送りたい` / `長文` などを検索し、主要機能を選ぶ。
3. deadが初期候補に含まれないことを確認し、「終了／到達不能も含める」で明示表示する。
4. OSSの「架空ソース」を開き、外部遷移せずページ内の安全なモック先が説明されることを確認する。
5. 「機能の根拠詳細」またはNIPチップから、対応状態、架空根拠、観測日時、観測主体、公式NIP一次資料への導線を確認する。
6. 2〜3件を比較に追加し、「機能で比較」を開く。機能行が主で、OS等の基本情報も比較できることを確認する。
7. UI STATE LABで loading / empty / error / partial / offline を切り替える。
8. 幅375pxで横溢れがなく、詳細フィルターが初期折りたたみで、候補が先に見えることを確認する。

### NIP一次資料とモック制約

NIP番号・英語見出し・用途ラベルは、公式 `nostr-protocol/nips` リポジトリの commit `656cecc7c0a815b6a2b218d3b5d6f078b3f4dbab`（2026-08-15確認）に照合しています。採用NIPは 01 / 02 / 05 / 09 / 11 / 19 / 21 / 23 / 25 / 42 / 44 / 46 / 47 / 57 / 65 / 78 です。改修後もこの公式一次資料確認commitを維持しています。

**36件のツール名、各機能の対応状態、OSS表示、根拠、観測日時、観測主体はすべて架空のUIモックです。** 実在するクライアント、リレー、ライブラリ等の実装状況や品質評価として利用できません。`不明` は材料不足による保留であり、未実装・非対応という否定評価ではありません。

共通架空データは `data.js` に分離し、A/B/C/Dで同じ36件を利用します。Dでは既存の架空NIP対応記録を機能単位に束ねて表示します。構成は引き続き純粋な静的ファイルのみで、**バックエンド、専用API、永続DB、中央インデクサを未来永劫作らない**原則を維持します。Nostr接続、署名、送信は実装しません。
